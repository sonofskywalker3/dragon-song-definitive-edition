# Test report: respawn on re-entry, area clear, blue chests, save glitch

Tested 2026-10-05 in BizHawk, patched ROM `build/par_c/dsde_c.nds` built from commit eafc271 (features
`restock-on-entry`, `no-clear-refill`, `no-virtue-clock`, `one-battle-mode`, `fix-save-glitch` and the rest of the
defaults), every run from power-on through `boot_from_save`. Comparison runs used the original ROM, copied to
`build/par_c_vanilla/vanilla_c.nds` (and `vanilla_csave.nds`) so it gets its own battery save; the post-intro save was
installed for it with `--save`.

| Test | Result |
|---|---|
| 1. Respawn on re-entry (and not while staying, not after a battle, not after the menu) | **Pass** |
| 2. Area clear: no HP/MP refill | **Pass** (original: +30% confirmed) |
| 2. Blue chest locked before the clear, opens after | **Pass** (same as original) |
| 2. Opened blue chest after leaving and re-entering | Stays opened (patched and original) |
| 3. Save glitch: talking to Flora twice keeps Save enabled | **Pass** (original: 0xCF set, Save struck out) |

No bugs found in the tested features.

## Plans

Generated by `emu/gen_fld_plans.py` (Delrich Temple, map 6, dungeon group 1 = maps 5 to 19, map index 1, enemy table
entry at 0x020B490E: clock, limit, kills at 0x020B4912, total at 0x020B4913). `emu/run_fld.sh <rom> <out> <part1>`
runs them in order; each part ends in a savestate the next part loads (all from one power-on chain on the same ROM).

| Plan | What it does |
|---|---|
| `fld_1_arrive` / `fld_1_arrive_vanilla` | Power-on, `fld_cheats` (ATK/DEF/AGI pins, HP left alone), `warp6`. Jian lands on a symbol, the battle is won with A presses. The original forces Virtue mode (`poke u8 0x020B4848 1`) so its kills count. Saves `fld_k1` |
| `fld_2_respawn` | Second battle, wait 1500 frames, open and close the menu, try the blue chest, door to map 7 and back. Saves `fld_back` |
| `fld_3_round` | One battle; repeated until kills == total |
| `fld_4_after_clear` | Blue chest after the clear, door to map 7 and back, blue chest again |
| `sg_flora` | Save glitch test (both ROMs) |

Harness tricks used (test only):

- Battles on demand: pin the x/y words (+4, +8) of map objects 2 to 9 onto Jian for 10 frames. The field contact
  check (`|dx| < 0xA000 && |dy| < 0xA000` against the player, field state 0x14) starts the battle. Between battles the
  remaining symbols are pinned on a far spawn point (0x138, 0x220) so none walks into Jian during the chest and door
  steps. (An earlier attempt without this hit a random battle at the chest, and the door poke then landed inside the
  battle.)
- Doors: a door trigger sets the destination at 0x020B77EC (map), 0x020B77F0 (0x270F), 0x020B77F2 (entry) and field
  state 0x86 (seen by watching a real door: Jian's room door goes 0x14, 0x86, 0x8D, 0x8E, 0x8F, 0x58, 0x59, 0x63,
  0x64, 0x11, 0x14). The plans poke those values, so everything after the trigger is the game's own door path. The map
  load (`func_0201d92c`) then gets load flags 0xFFFFFFB1; a real door walk (`warp6`) passes 0xFFFFFFBF. Both have bit
  0x20, the bit that gates the enemy-table code at 0x0201E0EC.
- Pins are not part of a savestate, so every part re-includes `fld_cheats` after `load`.

## 1. Respawn on re-entry

Patched (`build/par_c/log_1.txt`, `log_2.txt`):

| Step | kills / total on map 6 | Enemy symbols (kind 3) on map 6 |
|---|---|---|
| Arrival | 0 / 5 | 5 |
| After battle 1 | 1 / 5 | 4 |
| After battle 2 (map reload with flags 0xFFFFFF5E, no entry init) | 2 / 5 | 3 |
| After 1500 frames of standing in the field | 2 / 5 | 3 (no respawn) |
| After opening and closing the menu (map reload with 0xFFFFFF5E, no entry init) | 2 / 5 | 3 |
| Door to map 7 (entry init runs for map 7: 0 / 7); map 6's entry untouched | 2 / 5 | |
| Door back to map 6: entry init at 0x0201E0EC runs | **0 / 6** (total rerolled) | **6** (fresh symbols at spawn points) |

Original game, Virtue mode (`build/par_c_vanilla/log_2.txt`): after two kills the Virtue clock revived one
(kills 2 to 1 at frame 7260 while standing). Door to map 7 and back: the entry is kept (kills 1 / total 5, clock 0x677
carried over) and 4 symbols come back, i.e. no restock inside a dungeon group, as documented.

The same behaviour was seen in an earlier exploratory run (kills 2/5 with 3 symbols, after the door round trip 0/6
with 6 symbols).

Screenshots: `build/par_c/f_wait.png`, `f_menu.png` (menu open, "Delrich Temple"), `f_map7.png`, `f_back6.png`.

## 2. Area clear

### No refill

Before every clearing battle the plan sets Jian to 20 HP and 1 MP (level 5: max HP 77, max MP 15).

- Patched (`build/par_c/log_r6.txt`): the sixth win makes kills 6 / total 6. F+0xC64 (0x020B7848) never becomes 1,
  field state goes 0x7B, 0x29, 0x11, 0x14 (no 0x1B, no 0x3C). HP 19 (20 minus battle damage), MP 1 afterwards: **no
  refill**.
- Original (`build/par_c_vanilla/log_r6.txt`): the clearing win (5 / 5) sets 0x020B7848 = 1, then field state
  0x11, **0x1B, 0x3C** (statue sparkle), 0x14, and HP 17 to 40 (+23 = 30% of 77), MP 1 to 5 (+4 = 30% of 15).

Screenshot: `build/par_c/f_round.png` (after the last round), `build/par_c/f_cleared.png`.

### Blue chest

Map 6 object 1 is a blue chest: kind 4 at (0x41C, 0xD4), +0x22 needs-clear = 1. Jian is placed below it facing up
and presses A three times.

- Before the clear (kills 2 / 5): nothing happens, +0x20 stays 0, field state stays 0x14, no message
  (`build/par_c/f_chest_locked.png`). Same on the original (`build/par_c_vanilla/f_chest_locked.png`).
- After the clear: field state 0x42 to 0x45, +0x20 = 1, message "Got Mental Bandana" (`build/par_c/f_chest_open.png`).
  Same on the original.

### Opened blue chest after re-entry

After opening, door to map 7 and back:

- Patched: map 6 restocks (kills 0 / total 6, 6 symbols) and the chest is still opened (+0x20 = 1 right after the
  map load); A on it does nothing (`build/par_c/f_chest_reenter.png`). The open state is kept by the game, so the
  restock cannot give the chest again.
- Original: same open state; kills stay 5 / 5 and no symbols come back.

Not tested: an **unopened** blue chest on a map that restocks before the player cleared it (expected: locked again
until the new total is beaten, by the same `func_0206ec84` check).

## 3. Save glitch (Flora in the Underground Tunnel)

Setup (`emu/plans/sg_flora.plan`): story context at 0x02204620 (`*(u32*)0x020B4640`); byte +0x19 holds flags 0xC8 to
0xCF. Set flags 0xCA (Flora back in the tunnel, set by script 020 at Elda Canyon), 0xCB (her join event done, script
010) and 0xCC (she left, script 019): byte 0x1C. Party Jian, Gabryel, Rufus. Door from Jian's room with the
destination pinned to map 50 (Underground Tunnel, script 10; the menu shows "Underground Tunnel"). Flora is map object
6, talk id 0xA0, at (0x2D0, 0xA4); Jian is placed below her and talks twice, then Menu, System, Save.

| | Patched | Original |
|---|---|---|
| Talk 1 | "That's just too much! I did my best..." then "I want to go along..." | same lines |
| Flag 0xCF (byte 0x02204639 bit 7) | stays clear (0x1C) | **set** (0x1C to 0x9C) |
| Flag 0x5E (byte 0x0220462B bit 6) | set (0x00 to 0x40) | stays clear |
| Talk 2 | only "I want to go along..." (the said-once branch works on 0x5E) | only "I want to go along..." |
| Menu > System > Save | enabled; pressing it opens the save album screen | struck out in red; pressing it does nothing |

Screenshots: `build/par_c/save/sg_talk1_a.png`, `sg_talk2_a.png`, `sg_system.png`, `sg_save_pressed.png` (save album);
`build/par_c_vanilla/save/sg_system_save.png` (struck-out Save), `sg_save_pressed.png`.

The game was not actually saved (the album was opened, nothing written).

## Notes and side findings

- Contact check (decomp ~line 27995): an enemy symbol starts a battle only when (+0x18 & 0x1FFFFF) >> 13 == 0 (the
  no-contact timer) and it is within 0xA000 (10 px) of the player in both axes.
- The Virtue clock on the original runs between battles (clock 0xC9E before one round); with long field waits it
  revived kills during the comparison run, which is why the original needed six rounds for its five enemies. The
  patched clock stayed 0 throughout.
- The patched game still draws the frozen clock HUD and kill counter (known, see design item 2).
- Camera after teleporting Jian in the tunnel: parts of the map show as blue because the background was streamed for
  the entry position (harness artefact, not a game bug).
